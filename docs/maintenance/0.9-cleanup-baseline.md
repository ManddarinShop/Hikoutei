## f. 유령 파일 인벤토리 (hypothesis — 실행 안 함)

- 레포 루트에 `:memory:<uuid>` 파일 **117개** + `.hikoutei-setup-state.json.bak-20260828` **1개**
  (후자는 `.hikoutei-setup-state.json`의 날짜 붙은 수동 백업 복사본 — 사용자 데이터,
  본 작업에서 손대지 않음).
- **생산자 가설** (Phase 1 수정 대상):
  1. `test/public-adopt-api.test.ts`(및 일부 adopt 계열 테스트)가
     `dbName: `:memory:${randomUUID()}``로 유일 인메모리 DB를 의도한다 (6곳).
  2. `src/adapter/persistence/providers/mikro-orm/storage/MikroOrmSqliteAdapter.ts`
     ~156행의 `initializeMikroOrmSqliteAdapter()`가 `dbName`을 **그대로**
     `MikroORM.init({ dbName: options.dbName, driverOptions: new NodeSqliteDialect(options.dbName) })`
    로 전달한다 (확인됨).
  3. node:sqlite(`DatabaseSync` 기반 NodeSqliteDialect)는 `":memory:"` **정확히
     일치할 때만** 인메모리 DB로 취급하고, `:memory:<uuid>`는 파일 경로로 해석한다.
     그 결과 `<uuid>`가 달라질 때마다 CWD(레포 루트)에 `:memory:<uuid>` 파일이
     생성·축적된다.
  4. 보강 증거: `src/internal/syncStatus.ts:226`도 `dbName === ":memory:" ||
     startsWith("file::memory:")`만 인메모리로 판정 — `:memory:<uuid>`를
     인메모리로 인식하는 코드가 어디에도 없다.
  5. `:memory:` 정확 일치(`dbName: ":memory:"`)를 쓰는 다른 테스트들은 파일을
     남기지 않는다 — 유령 파일 수(117)가 `:memory:${randomUUID()}` 사용 테스트의

## g. v1-freeze 예외 구역 지도

`design/v1-design-freeze-and-implementation-checklist.md`의 동결 정책 기준.
아래 구역의 knip/tsc 지적은 **죽은 코드가 아니라 계약**일 수 있으므로,
Phase 1에서 개별 결정 없이 함부로 삭제하지 않는다.

- **canonical-commit 경로**: `src/application/sync/service/` (SyncServiceBootstrap,
  syncAutoStart, polling/effect supervisor, adopt/ 시딩·채택 경로).
  knip 지적 `configSchemas.ts`, `serviceOptionSchemas.ts`, `InternalSyncProvider`,
  `ExistingSheetAdoptionErrorCode` 등은 이 구역 안 — 단일 SQLite 트랜잭션에서의
  canonical commit + effect outbox 기록 계약(`v1-design-freeze` §경계)과 직결되므로
  "미사용 = 삭제" 확정 전 서비스 옵션 계약 문서와 대조 필요.
  `commitCanonicalChangesWithAdapter`(`storage/state/canonical/canonicalCommit.ts`)
  도 동일 — canonical commit 경로의 어댑터 주입 계약.
- **`src/infrastructure/storage/state/**`**: SQLite canonical projection
  (state/canonical, mapped, observation, resolution) — System_State가 SQLite
  canonical projection이라는 v1 경계의 구현부. resolutionWriter/observationWriter의
  미사용 상수·타입은 스키마/상태 전이 계약과 연결되어 Phase 1에서도 증거 확인 후에만 손대는 구역.
- **`packages/ikisaki` 공개 서피스**: 게시된 일관성 큐 패키지 (`@hikoutei/ikisaki`,
  npm 게시). knip의 `outbox.ts` 타입 3건, `outboxSql.ts` `FENCE_EXISTS_SQL`,
  `EFFECT_BATCH_LIMIT|MAX_IN_FLIGHT_EFFECTS` duplicate export는 **게시된
  계약 표면** — root가 소비하지 않아도 npm 소비자 계약으로 결정 문서(h)에서
  처리해야 한다 (fencing/fencing-exists SQL·effect 배치 상한은 freeze 문서의
  worker 단일 작성자/fencing 항목과 직결).
- **quarantine/fencing**: row identity 불명확 시 추측하지 않고 quarantine한다는
  v1 정책 구현(`state/resolution/**`, `candidateEvidence.ts`의
  `presenceCandidateVisibleEvidence` 등)은 위 구역에 포함되어 예외 대상.
- 위 구역 **바깥**의 knip 지적(provider index 재수출, shared barrel, cli 지역
  상수 등)은 자유 정리 대상 후보다 (아래 Phase 1 candidates).
